FINAL LIST OF KNOWN DIFFERENCES BETWEEN THE PORT AND MAME (M10-26, task 17; updated by task 75, 2026-10-21)
================================================================================================

Plain text, no ROM data. This is a list for people, not a rule file for diff.py. The rules that diff.py reads are still in re/harness/allow/*.txt (m1, m10, m10_runs, m2,
m228, m3, m313, m3e, m4, m5, m6, m7, m8); this file says why each kind of difference exists. How to read it: every cause has a number (C1, C2 ...), a short description,
the original address when a source names one, the recordings and record ranges, and a line "Player sees:" (picture, sound, play, or "trace field only").
A cause or row marked GONE has no difference on the newest build any more; the mark names the task or merge that removed it.

Where the facts come from: the allow files above, the sweep tables of Desktop Haiku (re/out/desk/dhaiku/sweep.md: 418 recordings, refresh 10: 406 equal in step mode;
sweep_new.md: 318 recordings, 313 equal; the files results.jsonl and results_new.jsonl named in the task are not on disk: re/out/sweep is gone, the tables in the two .md files
and the report of task 69 were used), plan/game/design/D5-errata.md, the reports of the Desktop workers (re/out/desk/*/report.md), and the checks of 2026-10-21 (Task 75): section 9.

Where things stand:
 - Whole runs (re/harness/m10_all.sh): the natural recordings of Episodes 1 to 8, 1 to 3 players, the ending, game over and the attract loop after it: step and lagsync mode are
   equal to MAME in every record except the records listed in sections 1 to 4. m10_all.sh: 134 of 134 mode runs equal with the rules (Desktop Opus task 26). Run mode (a free run
   from the snapshot) is equal up to the first MAME lag record of each recording, then it drifts: cause C1.
 - re/harness/regress.sh: 52 of 52 scenarios with 0 differences.
 - The attract loop from power on (attract3, 29475 records): equal in every record from 25 on under the rules of allow/m1.txt sections 1 and 2 and allow/m10.txt; 403 of 416
   pictures are pixel exact (section 5).
 - Nothing in this list changes the rules of play, the damage, the scores, the drops, the enemies, the bosses or the ending. What a player could notice is under "Player sees:".

1. DIFFERENCES THAT THE PORT HAS ON PURPOSE OR BY PLAN DECISION
------------------------------------------------------------------------------------------------------------------------------------------------------------------

C1  Slowdown (CPU time) is not modelled.  [plan decision R12 / item 13; D5-errata M3-29, M6-17 item 1 and 2; Desktop Haiku tasks 52 and 53]
    The original runs a game frame longer than a video frame when much happens (many objects, the area start 0x20766, the stage clear, a scripted walk): MAME marks such a record
    as a lag record (1606 of 1,151,836 records in 24 natural recordings, 0.14 %); the game counter G.$0 jumps by 2 or more in it. The port runs every game frame in one tick, at the
    frame rate of the original, and has no model of the CPU time (flow.lag is set only where the time is known: the ending, the character select, the game over exit).
    Covers: every recording in run mode after its first lag record (ep1_3p 2544, ep2_3p 4044, ep2_jack 4503, ep3_3p 2637, ep3_hannah 7377, ep3_jack 9463, ep3_mess 9710,
    ep3_mustapha 7413, ep4_3p 4401, ep4_jack 2757, ep5_3p 1993, ep5_hannah 8477, ep5_jack 6135, ep5_mess 8362, ep5_mustapha 3223, ep6_3p 4244, ep6_jack 5912, ep7_3p 2303,
    ep7_jack 2267, ep8_3p 1971, ep8_hannah 5339, ep8_jack 4131, ep8_mess 2662, ep8_mustapha 5234). The lag records themselves are left out of diff.py in step and lagsync mode.
    A lagsync run (MODE=lagsync) loads MAME's state after each lag record and after a record whose game frame count differs, and is equal to MAME in between.
    Player sees: yes, in play. Where the arcade board slows down under load (many enemies, shots or explosions), the port keeps its constant pace (README: "No Arcade Hardware
    Slowdown"). Nothing else changes: the objects do the same in the same game frames.

C2  The skip wait: a fixed 3 rounds a tick (cause K in allow/m10_runs.txt).  [flow/skip.rs; task 0x9E38C; plan decision]
    While a hero holds attack or jump in a scripted scene (the stage clear walk, an entrance, a dialogue, an area change), the original runs as many game frames in a video frame as
    the CPU time allows (2.2 to 5 measured); the port runs 3. In the one record where the count differs, every counter of every object differs by the missing rounds (objects, timers,
    scripted flags); lagsync resyncs there and is equal afterwards.
    Covers (step mode, one record each): ep1_3p 6144, 6177, 6193; ep3_jack 9476; ep3_mess 9909; ep3_3p 8318; ep4_jack 27497, 27532; ep5_jack 40143, 40150, 40161; ep5_hannah 57870;
    ep5_mess 45375; ep6_jack 65578-65579, 65602, 65770-65779 (the catch-up records of the scripted walk-out); ep7_jack 34860; ep8_jack 33713; ep8_mess 64981, 67151; ep8_3p 62386, 62433.
    Player sees: yes, only while holding attack or jump to hurry a scripted scene: the scene runs a little slower or faster than in the arcade. Nothing else.

C3  Port features that the arcade does not have, and arcade features that the port leaves out.  [README: "What Is Not Included"; run.md]
    Port only: the move keys A S D F G (they press the original buttons with the original timing), the combo toggle Q (the third punch of a chain plays the command move), P (pause),
    F1 (hit boxes), fullscreen, the keyboard and gamepad mapping, the settings file dino.cfg in place of the operator menu, the debug flags (--jump, --test, --debug-keys, --autoplay),
    the computer allies (--ally, F7 / F8).
    Left out: the operator test menu and the EEPROM edits (N01 of the audit: "partly present": the settings file and the difficulty bits), other region sets (only the World set
    "dino"), the arcade debug mode (the debug dip switches and the routines behind G.$4AA: the ground marker 0x939B6 and others are never reached in play), the arcade slowdown (C1).
    Player sees: yes, in how the game is controlled and set up. The game rules are the arcade's.

C4  Voice lines of the team move.  [D4e open item 3; audit row M25]
    The team move has no voice request in the ROM (the web sources name "Take that" and similar lines); the port sends none either, so there is no difference to the ROM. Listed
    because the audit row M25 stays "missing" in plan/game/design/M9-audit-c.md.
    Player sees: sound only, and only if the web claim is right.

C12 Registers left in d1 / d2 by earlier code.  [allow/m10_runs.txt M10-22 R1 to R6; allow/m4.txt section 4; D5-errata M4-17, M4-19; allow/m6.txt rule 2]

       reads no d2 in mode 0 (0x0251 -> 0x0279): what plays is the same.
    R2 The landing voice 0x62 / 0xDE / 0xDF (0x9C0C at 0x1A8F4 / 0x1B6DE) and the high word of the pick-up voice's d2 (0x9C20 at 0x1983A after 0x5AA2): the register of the frame code

    R4 Music codes 0x00 .. 0x26 (0x017D -> music_start reads no request byte): d1 / d2 are the registers of the code before the call (frame words of an animation step 0x121E,

    R5 The jungle call 0x78 of pool B class 80 (0x8A5E0): the high word of d2 is left by the code before; d1 = 0 (mode 0).
    R6 Fessenden's hold (class 84, 0x62876 / 0x62938 -> 0x125C0 -> 0x1266E): the pan of the hit sound is the X of a2, a register of the code before the enemy loop (MAME pan 0 in
