# Rank cross-check

Ground truth is `dino-rs/crates/dino-game/src/game/rank.rs`, enemy spec section 6, and the rank notes in `D2b-player-state-rules.md`. The fan text is the "Rank system" section of `claude-doc-deep-dive-supplement.md` (mechanics row M22) and the operator list in `claude-doc-deep-dive-supplement-2.md` (row N01).

Two names: the fan's normal rank is `w.rank` (G.$5F0, 0..31). The fan's timer rank is `rank.speed` (G.$5F6, 0..15). The port's factory settings byte is `Settings.dip_b = 0x4B` (`flow.rs`, original 0xACBF4). Bits 0..2 are difficulty 3. Bits 3..4 are 1. That is N01's Normal for both difficulty settings, and the fan's defaults (setting 1 = 3, setting 2 = 1). `flow_mode_init` copies that byte into `rank.dip` before `rank_game_start`. A fallback in `rank_tick` still writes `dip = 3` if it runs first, which drops the speed bits.

Frames below are game frames. 600 frames is 10 seconds at 60 Hz.

A wait under 720 frames (G.$4F6, bands in table 0x180B4) picks the top row at 0x180FA. In that row, 20 of 32 rolls are those eight numbers, 8 rolls are +1, and 4 rolls are +2. ## Other sentences in the same section

- On a miss, timer rank does not fall by the same amount as normal rank. If the dying player still has a life (`+$A3 != 0`), `rank_event_continue` adds a speed delta from 0x187F4. At difficulty 3 that is −4 (1 player), −3 (2 players), or −3 or −2 (3 players, a random choice). The call is unwired.
- A continue is supposed to call `rank_speed_add` (0x18566) with −2 (D2b and D4d: d0 = 0xFE). No port call does that. NOT IN THE PORT.
- A miss at zero lives is supposed to call `rank_event_1842c` (0x1842C), which adds the word at 0x187DE (−1). The function matches the fan's "−1, not stacked". `player_dead_continue` does not call it.
- "Timer rank 15 by episode 4 if you have not died" is a play claim. No such test is in the code. UNKNOWN.

## Missing from rank.rs

The functions above are in `rank.rs` unless the note says the call is elsewhere. These parts have no writer in the port:

1. G.$4F6, the title-wait counter. `rank_game_start` reads it. The system task 0x1827A counts it (spec 6.1, D4d).
2. The death, join, and continue calls. Death should call 0x184E2 from 0x1BFF0 / 0x1C020, and 0x1842C when no lives remain (spec 6.4, D2b 2.2). A join should call 0x18410 (D4d, join path near 0x7072). A continue should call 0x18566 with −2 (D4d 6.3). An extra life should call 0x1843C from 0x6BDC (spec 6.4).
3. Pending rank-ups G.$5FA and rank-downs G.$5FC. `rank_tick` spends them (1800 frames per up, 1200 per down) and `rank_game_start` clears them. Section 6 names no writer.
4. Rank freeze G.$602. `rank_tick` and the event functions test it. `rank_game_start` (0x17F8A) and `rank_area_start` (0x18048) clear it. Section 6 names no setter.
5. G.$4DD. `rank_tick` tests it. The area walk that should set it is 0x1D95E (spec 6.3 and the boss-end note). The port never writes `w.scripted`.
6. The operator menu. Rank only reads the one settings byte. N01's other options (bonus life, lives, coins, continue, flip) are outside `rank.rs`. The byte the rank code uses is the factory default in `flow.rs`.
