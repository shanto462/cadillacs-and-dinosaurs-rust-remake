# Approved known differences of the story panels (mode 8) and the level start after them, M2-26 to M2-28 (re/harness/link_check.sh, tally_check.sh). The rules that
# depend on the recording (frame ranges: the pointers of the stage that is poked in until the level starts, the first level frame, the cuts at the video frame
# boundaries, the display shadows) are added by re/harness/story_allow.py, which prints this file first.
#
# The runs start from a level of Episode 1 (the recorder's jump helper) into which the recording pokes G.$4D9, G.$4D1 and G.$4D0 = 8 at t = 0.
#
# The jump helper leaves the live byte of the hero 2 (in play), the game itself has 1 (the tally recordings: 1 all the time). The byte is 1 in MAME from the
# frame of the poke on (what writes it is not known: a hold of the recorder's jump); the story panel code tests it for 1, so link_prep.py gives the port
# the same write at frame 0 (the pokes file).
# (0xAE0 clears both sprite buffers while the sprite list builder is not running (mode 8): MAME's list has its 256 entries, all zero, and no end marker; the port
# exports the same, `SpriteList::blank`.)
# G.$860 / G.$868 (the scroll shadows of the display) are copied from the cameras by the game loop after a pass of the game task; the first pass of the mode 8
# routine (0xAE0 keeps the CPU through 2 frames) does not reach it, so they keep the level's values for 2 frames. The port derives them from the cameras.
global.display_y2 0-1
global.display_y1 0-1
