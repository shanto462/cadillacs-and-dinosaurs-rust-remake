# The poke file holds four lines `RECORD 0xFF8014 2 VALUE` (`#!clock game` first): G.$14, the random number state, is set from the
# recording in the record each demo returns (4668, 11239, 17773, 24344). The demos draw random numbers in objects of classes the
# port does not run yet (the levels are incomplete until M10-03 to M10-05), so the state they leave is not the original's; without
# the four lines every screen after the first demo would differ in the random numbers of the clouds and heroes of the ranking.
# The test `attract_loop_two_loops_match_mame` (dino-rs, `cargo test`) compares the whole loop record by record (tilemaps, palettes,
# sprite list, layer control, sounds, state byte, scroll shadows, G.$14) with NO allowed difference outside the demos: that test is
# the gate for the screens, this file lists what the field by field diff shows. Since M10-03 the demos play their real levels and
# leave the original's G.$14: the test sets nothing any more, the poke file is not needed (the demos themselves: allow/m10.txt).
# The records are trace records (video frame - 2). The demos are the records 3343-4667, 9914-11238, 16448-17772, 23019-24343
# (A .. A + 1324, A = the record in which the title returned and G.$757A stepped), after them come the clear of the next screen
# (the records 4668, 11239, 17773, 24344 and the next one).
#
# Not compared by this file (the picture of the screen, not the state): the frames where MAME's picture and the port's picture
# differ although every record is equal are listed at the end, with their causes.

# 4. Picture differences. Not rules of this file (diff.py compares records, and every record outside the demos is equal there); they
#    are the frames where MAME's picture and the port's picture differ although the records are equal, listed with their causes.
#    How they were found: 416 video frames of the loop (list: the two probe batches `re/out/probe/m115_loop` and `m115_loop2`, a
#    `snaps` line, MAME headless) against the port's `--screenshot out.png --frames N` with N = frame - 1 and the poke file above,
#    `re/harness/probe/shotdiff.py MAME_DIR PORT_DIR --clock f` (exit 1: the frames below). 369 frames are pixel exact: the boot, the
#    title (every start of it after the first), the four profile cards (first and later runs, every card start), the ranking (every
#    start after the first), every cut of the five story slides, and the opening movie, three runs of each in both loops.
#    A picture is made from the tilemaps of the record, the palette of the record before, the scroll registers of the record two
#    before and the sprite list built two records before (`present.rs`, `camera.rs`, `vram.rs`: the model that fits every normal frame).
#    The original latches the palette and the video registers in the interrupt; where the CPU is still busy with a pass at that moment
#    the picture is a frame ahead of or behind the model. All of these frames belong to the FIRST run of a routine after power on (the
#    first boot, the first profile cards, the first ranking), which the records show running one frame ahead of the later runs; nothing
#    else in the loop differs:
#      video frames 322 and 2746 (records 320 and 2744, the first frame of the first title and of the title after the first ranking):
#        MAME already shows the title's palette (the new colours), the port the palette of the record before
#      935, 1280 and 1281 (records 933, 1278, 1279, the first run of the profile cards, two passes of the task in one frame): the
#        sprites of the card (portrait and small hero) and one fade step appear a frame earlier in MAME
#      2323, 2324 and 2325 (records 2321 to 2323, the start of the first ranking): the video registers did not change in the records 2319
#        to 2321 in MAME (cpsa scroll3 Y stays 0x93E, the call needs about four frames of CPU time; the registers keep their value
#        until record 2322), so MAME shows the old palette in 2323 and the scroll3 map shifted by 64 pixels in 2324 (no sky); the
#        port, which latches every frame, shows the new colours. Tilemaps, palettes, shadows, sprite list: equal in every record
#      2745 (record 2743, the last frame of the first ranking): the scroll registers are one frame different, a speckled desert
#    Other differences, all known and not M1 code mistakes:
#      12900 and 12910 (the shakes of the dinosaur in the movie; M1-11 found 12970, 12980, 13030 and 13040 too: the three shakes, 6
#        of 106 pictures): `screen_shake` 0x222D6 is a stub until M3-10, the request is made but the scroll2 Y offset is not
#        applied. Listed, not ported
#      13380 (record 13378, the last clear of the movie): MAME's picture still shows stale scroll3 cells outside the window that the
#        renderer hides (tile codes outside 0x1C00..0x1FFF), see D5-errata M1-10 and M1-11
#      3346 to 4670, 9925 to 11200, 17000 to 17600, 23060 to 24200 (the demos): level content that is not complete, see 3.
