# 4. Picture differences. Not rules of this file (diff.py compares records, and every record outside the demos is equal there); they
#    are the frames where MAME's picture and the port's picture differ, listed with their causes.
#    How they are found: 416 video frames of the loop (the two probe batches `re/out/probe/m115_loop` and `m115_loop2`, a `snaps` line,
#    MAME headless) against the headless renderer (`dino-game --headless --screenshots N --shot-dir DIR`, N = frame - 1, no poke file),
#    `re/harness/probe/shotdiff.py MAME_DIR PORT_DIR --clock f`: `re/harness/m10_loop_check.sh`. Result (2026-10-21, after the picture
#    model below): 403 of 416 frames are pixel exact (385 before), every frame of the second batch included.
#    The picture model (`present.rs`, `camera.rs` `Camera::shown_scroll` / `shown_layers`, `draw.rs` `SpriteList::latch`, `vram.rs`
#    `PaletteRam::latch`) follows the vblank IRQ 0x542, which runs after each record. The picture of record r shows:
#      the tilemaps and the CPS-B priority masks of r (written in the frame);
#      the palette of r - 1 (0x81C writes the palette base, the CPS-B copies the palette then);
#      the layer control G.$28 (0x80A), the video control G.$26 (0x826, the row scroll bit) and the scroll3 base G.$2E (0x57A) of r - 1;
#      the scroll X registers and the scroll3 Y: the shadows of r - 2 (0x6C0: each register takes the IRQ's copy G.$85C / $864 / $86C /
#      $870, then the copy takes the shadow);
#      the scroll1 and scroll2 Y: the copies G.$860 / $868 of r - 1 (the shake routine 0x22356 / 0x22364 writes these copies in the frame,
#      so they are not always the shadows of r - 2);
#      the sprite list built in r - 2 (0x554 points the OBJ base at the buffer built last, the video copies it at the next vblank).
#    MAME's CPS-A / CPS-B registers in attract3.mame.trc fit this in every record from 41 on, except where an IRQ of the first loop did not
#    run (below). The model before took the scroll1 and scroll2 Y one record too late (G.$868 of r - 2, since G.$868 became a port field)
#    and the layer registers one record too early: that was the cause of 17 of the 22 "starts of a screen" listed before (the first frame
#    of each ranking, of the title after the later rankings, of the story slides, the jungle of the movie: screens where the camera Y or
#    the layer control changed; the other five are first runs or demo setup records, below). Scroll3 shows every tile code 0 .. 0x1FFF: a cell 0 or a stale cell shows the graphics ROM read as 32x32
#    tiles where scroll2 is transparent (`dino_assets::TILES32_COUNT`); this made 12900, 12910 (the dinosaur's shakes, one or two pixels of
#    scroll3 cell 0) and 13380 (the stale scroll3 cells of the last clear of the movie) exact.
