# ep2_jack, ep2_3p, ep3_jack, ep3_hannah, ep3_mess, ep3_mustapha, ep3_3p, ep4_jack).
# Lines "NAME.MODE: key range  # reason" apply to one recording and one mode (MODE step, lagsync, run or *); m10_check.sh cuts them out to a plain allow file for diff.py.

# Results (see re/out/desk/dsonnet/report.md, "Task 11"): ep3_hannah has no difference in step and lagsync mode. In run mode every recording is equal up to its first MAME lag record
# (ep2_jack 4503, ep2_3p 4044, ep3_jack 9463, ep3_hannah 7377, ep3_mess 9710, ep3_mustapha 7413, ep3_3p 2637): the slowdown of the original is not modelled (plan decision), the free
# run is not compared after a lag record (that is what lagsync is for). Not listed here: the run mode tails after the first lag record.
#
# Causes (each rule names its number):
#  S  The story panel after the stage clear (mode 8): the first frames of it lie in MAME lag records (the panel's routine runs 3 or more game frames inside one video frame). The step
#     and lagsync loaders cannot restore a routine that sleeps inside the story panel (`Story::part`, `Flow::wait` and `Flow::resume` are not in RAM, the stack of the task is not read
#     for the panel), so the port starts the panel from its first part in the record after the load: the frame counters G.$0 / G.$4DA are one more, the camera of the panel
#     (G.$744, G.$7E4, G.$7E8) and the scroll layers start again, the sound 0x15 of the panel comes a frame early. The panel itself is checked by the link recordings of M2-28 (free run
#     from the stage clear, allow/m228.txt). G.$77E (map_ptr) is derived from the stage number, which the port has already counted up at the panel; the original keeps the old map until the
#     stage start (the same as allow/m228.txt "the derived pointers").
#     (Since the story panel loader of `trace_load_tasks` reads the part of the panel from the saved return on the task stack, ends the staged entry clear (`clear_stage`, `clear3_cut`)
#     and restores the Episode 8 palette play (0xE0E4), the rules S of ep2_3p, ep3_jack, ep3_3p, ep4_jack, ep4_3p, ep7_3p and ep6_3p (except one counter) are gone. What stands: the G.$744 /
#     G.$77E of ep2_jack, the step mode of the four m517 Episode 1 runs, the coin pulse timer of ep6_3p.)
#  K  The skip wait (skip.rs, task 0x9E38C): a hero holds attack or jump in a scripted scene, the original runs as many game frames in a video frame as the CPU time allows (here 5),
#     the port a fixed number (SKIP_ROUNDS = 3, plan decision: the real number depends on the load of the frame, 2.2 to 4 in the other recordings). Every counter that counts game frames
#     differs by the missing rounds in that one record (the objects, the timers, the scripted flags). The next record is equal in step mode again; in lagsync the offset stays until the next
#     MAME lag record (the free run goes on with the offset), so the lagsync tails of ep3_mess and ep3_3p are this one cause.
#  P  The story panel's typewriter (pool B class 26) is made by the panel's routine at a point that the loader does not restore (cause S), so it is missing in the port for its life.

# M10-22: the sound request streams (re/harness/m10_sound_check.sh, snd_stream.py; step mode of all 30 natural whole runs). The keys `sound.CODE`, `sound.CODE.d1`,
# `sound.CODE.d2` (the code in hex, two digits at least) are read by snd_stream.py only (diff.py compares the codes, not d1 / d2). A rule without a recording
# prefix holds for every recording. A difference in a record whose state differs too is not listed: it belongs to the state checks above (m10_check.sh).
# Causes:
#  R1 The GO sign 0x3E (pool B class 20, 0x7BC58 and 0x7BD7A): neither the handler (0x7BB68 / 0x7BD40) nor the pool B loop 0x23604 writes d2, so d2 is the register
#     the update before it left (another object of the frame, seen 0x60, 0x70, 0xA, 0x4, 0xF000 ...). d1 = 0xA is the pan mode 0 (0x7BCCC), and the driver reads
#     no d2 in mode 0 (0x0251 -> 0x0279): what plays is the same.
#  R2 The landing voice 0x62 / 0xDE / 0xDF of the fall and drop landings (0x9C0C at 0x1A8F4 / 0x1B6DE) and the high word of the pick-up voice's d2 (0x9C20 at
#     0x1983A after 0x5AA2): 0x9C0C writes no d2 and the player update 0x18952 does not either, so it is the register of the frame code before (for player 1 the
#     code before 0x18834, for players 2 and 3 the update of the player before; seen 0x1F00, 0x4000, 0x3800, 0x60 ...). d1 is the pan byte (mode 0).
#  R3 The landing of an object that is no hero (0x9C20, 0xE0 / 0xE1, the class 20 library): the same register d2 (mode 0).
